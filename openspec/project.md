# 项目背景

## 目的
本项目旨在开发一个非嵌入式的 Shopify 应用程序。

## 技术栈
- Node.js (版本 22，pnpm)
- Shopify CLI (版本 3.x)
- 优先使用流行的、经过验证的库来解决问题。

## 项目约定

### 开发流程
本项目遵循行为驱动开发 (BDD) 和测试驱动开发 (TDD) 的混合方法，以确保软件质量和需求对齐。

1.  **调研**: 在实现任何功能之前，必须进行充分的技术和业务调研。
2.  **BDD - 需求用例**: 以 BDD 格式（Given-When-Then）清晰地列出功能需求和用户场景。
3.  **BDD - 验收测试**: 基于需求用例，使用与技术栈兼容的 BDD 测试库（例如 Cucumber.js）编写端到端的验收测试。这些测试用例在编码前完成。
4.  **图表设计 (如适用)**:
    -   对于涉及内部复杂逻辑的“纯功能”（例如，多步骤处理），使用 Mermaid 绘制 **流程图** 来可视化执行流程。
    -   对于涉及与外部系统交互的功能（例如，OAuth2 认证流程），使用 Mermaid 绘制 **时序图** 来明确交互顺序和协议。
    -   简单的函数计算过程不需要图表。
5.  **TDD - 单元测试 (如适用)**: 根据上述图表和功能细节，在编码前为“纯功能”编写单元测试用例。
6.  **编码实现**: 在所有相关的 BDD 和 TDD 测试用例编写完毕后，开始进行功能编码。
7.  **验收**: 通过运行完整的 BDD 验收测试来最终验证功能的正确性。

### 架构模式
- **库优先**: 优先使用流行的、成熟的库来构建功能，避免使用大型脚手架或自研解决方案，以确保代码的稳定性、可维护性和社区支持。
- **无模板开发**: 项目不采用任何预设的应用模板，以保持最大的灵活性和针对性。

### 测试策略
- **验收测试 (BDD)**: 所有功能都必须有对应的 BDD 验收测试，以确保其符合业务需求。
- **单元测试 (TDD)**: 核心的、独立的“纯功能”模块必须采用 TDD 的方式开发，以保证其逻辑的健壮性和正确性。
- 所有代码在提交前必须通过所有相关的 BDD 和 TDD 测试。

## 领域背景
- **应用类型**: Shopify 非嵌入式应用，意味着应用在 Shopify Admin 之外独立运行。

## 重要约束
- **技术版本**: 严格要求使用 Node.js 22 和 Shopify CLI 3.x。
- **开发纪律**: 严格遵守“测试先行”的开发纪律，即 BDD 和 TDD 测试用例必须在功能编码之前完成。
